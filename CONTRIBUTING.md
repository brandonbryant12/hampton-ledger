# Contributing

Start with an issue describing the source or resident question. Favor small, reviewable changes.

1. Keep figures tied to an exact reporting period and primary source.
2. Preserve originals and archive hashes; never edit a source snapshot in place.
3. Explain extraction and reconciliation limits.
4. Run `npm test` and `npm run validate`.
5. For interface changes, inspect desktop and mobile and verify keyboard navigation.
6. Do not publish accusations or personal information. Proposed findings need human review.

For another town, replace `data/sources.json`, the reviewed financial model, local labels, and methodology together. Source adapters and collection scripts are reusable; account mappings and legal rules are not assumed universal.
